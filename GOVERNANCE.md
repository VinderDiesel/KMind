# Governance

KMind follows an open, merit-based governance model.

## Roles

- **Contributor**: Anyone who submits issues, discussions, or pull requests.
- **Committer**: Trusted maintainers with write access.

## Path to Committer

1. Submit at least **5** merged pull requests that demonstrate sustained quality.
2. Participate constructively in design discussions and reviews.
3. Be nominated by an existing Committer.
4. Approval by a simple majority of current Committers.

## Decision making

- Routine changes: lazy consensus via PR review.
- Breaking API / schema changes: require Committer discussion and documented migration notes.
- Security issues: privately report to maintainers; coordinated disclosure.

## DCO

All commits must include a `Signed-off-by` line certifying the Developer Certificate of Origin.
